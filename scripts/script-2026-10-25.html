Why this matters

The agent conversation has moved past "can it do the task" into "can I leave it alone while it does the task." That is a different engineering problem. Every serious team hitting this wall lands on the same three failure modes: destructive actions that should never have been possible, third-party add-ons nobody vetted, and silent failures that look like success.

This week delivered a tool for each one, and all three are free to start.

The three layers, bottom to top

1. Enforce at the wire, not in the prompt

Vericto is a SQL proxy that sits between your agent and PostgreSQL or MySQL on the native wire protocol. It parses every statement into an AST, checks it against your rules, then either forwards it or returns an ordinary SQL error. A DELETE with no WHERE clause never reaches the database. Integration is a host and port change in your connection string. Source-available under FSL-1.1-ALv2: free to self-host in commercial production.

The lesson is bigger than the tool. Prompt-level guardrails are advisory. A parser sitting on the wire is enforceable, and it keeps working when someone swaps the model underneath it.

2. Grade anything you install

PlugVet is an independent directory that grades Claude Code skills, Cursor and Codex plugins, and MCP servers from A to F, publishing the checks behind each grade and the assessment date. It has graded more than 11,700 entries and holds F grades back rather than listing them. Free to browse.

Treat this as a ten-second first pass, not a security audit. It kills the obvious junk so you spend your reading time on the handful that matter.

3. Put a reviewer on every run

Kavela went into closed beta October 23 with a simple guarantee: agent automations that do not fail silently. Each run gets an isolated cloud computer with persistent file context, and a reviewer checks the output against a checklist you define before the run counts as complete. Fourteen-day free trial, no card.

Even if you never use it, copy the pattern. Add a validation step to your existing flows that scores the output against a fixed checklist and refuses to proceed if the score is low. That single change is what turns a demo into something you can bill a client for.

The mental model

Layer your defenses by where they sit. Ask three questions in order: Can this action even reach my system? Is the thing my agent is using trustworthy? Did the last run actually do what it claimed? Wire-level rules answer the first, directories answer the second, and reviewer steps answer the third. Most teams do all three of these in prompts and none of them in infrastructure, which is why they get burned.

Automation tip

Add a blast-radius test to every new automation before you trust it. Point the agent at a throwaway database or sandbox directory, then deliberately ask it to do the worst thing it plausibly could. Watch what happens. Ninety percent of agent accidents are not model failures, they are permission failures that were never exercised in a safe environment first.

Start today

Pick the one layer you are missing. If your agent touches any database, put a proxy in front of it this week. If your agent installs plugins, spend ten minutes grading what is already running. If your flows have no validation step, add one checklist gate to the highest-consequence workflow you own. One layer this week beats a perfect architecture you never build.
